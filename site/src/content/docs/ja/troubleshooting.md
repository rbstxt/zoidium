各項目は症状、原因、対処を挙げています。

## マテリアルパネルに「undefined」と表示される、または値が空になる

**原因:** Zoidium のグラデーションエディター使用時にマテリアルパネルの読み込みに失敗しました。現在のベータでは、パネルを止める代わりに標準コントロールにフォールバックします。

**対処:** エディターを再読み込みし、パネルを開き直します。それでも直らない場合はグラデーションエディターを切り替えます。

1. **Settings** を開きます。
2. **Gradient editor** を **Classic** にします。
3. エディターを再読み込みします。

## パーティクルに Smart Motion Blur が効いていないように見える

**原因:** 隣接フレーム間に動きが見つかりませんでした。隣接フレームが同一の場合、入力がそのまま出力されます。**Blur Amount** または **Motion Sensitivity** が 0 の場合も同じです。3D Scene の上の **Adjustment** レイヤーにエフェクトを配置した場合も、シャッター処理（Scene レイヤー上でのみ動作）を逃します。

**対処:**

1. **3D Scene** レイヤーに **Smart Motion Blur** を配置し、**Reconstruction** を **Automatic** にします。
2. パーティクルの **Time** プロパティをキーフレームで動かし、隣接フレーム間でシミュレーションが進むようにします。
3. 1 フレーム進めて戻し、パーティクルが動くことを確認します。
4. **Blur Amount** と **Motion Sensitivity** が 0 より大きいことを確認します。

[パーティクルとシーンのブラー](/docs/ja/how-to/motion-blur-particles-scenes/) に設定全体を説明しています。

## プレビューキャッシュが 0 フレームと表示される

**原因:** キャッシュ対象のフレームがまだないか、キャッシュが無効か、プロジェクトがキャッシュの対象外です。**Settings** の **Preview cache** コントロールの下に、カウント対象のメモリーと保持フレーム数が表示されます。対象外のときは、同じ行の最後に **Not caching:** と理由が表示されます。

**対処:**

1. **Settings** で **Not caching:** の後の理由を確認します。**Preview cache** の値を大きくしても、この理由は変わりません。
2. **Settings** を開き、**Preview cache** を 0 より大きくします。デフォルトは 512 MiB です。
3. まずフレームを通常どおり描画します。同じフレームとプロジェクト状態に戻ると、描画が再利用されます。
4. フレームを再訪する合間に編集、リソースの読み込み、解像度やプラグインの変更を避けます。いずれもキャッシュ済みの状態を無効にします。
5. 動画プロジェクトや描画の遅いシーンではバックグラウンドのキャッシュを期待しないでください。事前描画を省略します。映像が表示されている間は、約 0.8 秒操作がないときに一時停止中のフレームだけをキャッシュします。
6. 以前にメモリーの割り当てに失敗した場合、設定値を上げてもセッションの上限は下がったままです。GPU コンテキストを 2 回失った後は、エディターを再読み込みして取り込みを有効に戻します。

## 不足または失敗したプラグインが原因で書き出しが拒否される

**原因:** プロジェクトがコミュニティエフェクトを使っています。開発者プレビューではコミュニティエフェクトの書き出しはできません。

**対処:** エディターが **Export with missing or failed plugins** を提示したら、1 回限りの迂回を承認します。閉じたコンポジション内のエフェクトを含め、すべてのフレームですべてのコミュニティエフェクトを省略して書き出します。プロジェクトの記録は変わらず、選択は 1 回の書き出しにのみ適用されます。完全に書き出すには、不足したパッケージをインストールまたは修復してください。

## 不足したプラグインやアセットがある状態でプロジェクトが開く

**原因:** プロジェクトに必要なプラグインが無効か、アセットファイルが失われています。

**対処:**

1. エディターが要求するプラグインを表示したら、**Plugins** で有効にします。保存済みのエフェクト、マテリアル、オブジェクトの設定はプラグインと共に戻ります。
2. 不足または読み込み失敗のファイルは、[アセットを修復する](/docs/ja/how-to/repair-assets/) に従ってください。書き出しや新しいアーカイブの保存の前にファイルを再接続します。
3. 修復したプロジェクトを新しいアーカイブに保存し、コピーが正常なのを確認するまで以前のアーカイブを残します。

## エディターが遅い、または GPU メモリーが不足する

**原因:** ビューポートが重いシーンを変更のたびにフルサイズで再描画しています。

**対処:**

1. プレーヤーのツールバーで **Pause drawing** をクリックし、**1/8 quality** を選択します。
2. 確認が必要な変更の後に **Render once** を使います。
3. **Settings** で **Preview cache** の上限を上げ、再訪したフレームをメモリーから再描画します。
4. 書き出し中に GPU のメモリー不足やコンテキスト喪失が報告されたら、他のプロジェクトを閉じ、出力サイズを下げて再試行します。

[重いプロジェクトをプレビューする](/docs/ja/how-to/preview-heavy-project/) に手順全体を説明しています。

## バグ報告にデバッグログを添付する

**原因:** 環境情報のない報告は再現が困難です。

**対処:**

1. **Settings** を開きます。
2. **Debug information** セクションで **Download debug log** をクリックします。
3. ファイルの中身を確認し、報告に添付します。OS、ブラウザー、有効なプラグイン、直近のクラッシュの証跡を記録します。プロジェクトの内容は含まれません。
