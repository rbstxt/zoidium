よくある症状ごとに、原因と解決手順をまとめています。

## マテリアルパネルに "undefined" や空欄が表示される

**原因:** Zoidium のグラデーションエディターを使用中に、マテリアルパネルの読み込みが失敗しました。

**対処:** エディターを再読み込みし、パネルを開き直してください。解消しない場合は、グラデーションエディターを切り替えます。

1. **Settings** を開きます。
2. **Gradient editor** を **Classic** に変更します。
3. エディターを再読み込みします。

## パーティクルに Smart Motion Blur が効いていないように見える

**原因:** 前後のフレーム間で動きが検出されていません。隣接フレームが同一の場合や、**Blur Amount** または **Motion Sensitivity** が 0 の場合、入力画像がそのまま出力されます。また、3D シーンの上にある **Adjustment** レイヤーに **Smart Motion Blur** を置くと、**3D Scene** レイヤー専用のシャッターサンプリング経路が自動で選ばれません。

**対処:**

1. **Smart Motion Blur** を **3D Scene** レイヤー本体に追加し、**Reconstruction** を **Automatic** にします。
2. 前後のフレームでシミュレーションが進むように、パーティクルの **Time** プロパティへキーフレームを打ちます。
3. 1 フレーム進めて戻し、パーティクルが動いていることを確認します。
4. **Blur Amount** と **Motion Sensitivity** が 0 より大きいことを確認します。

詳しい設定手順は [モーションブラー](/docs/ja/effects/motion-blur/) を参照してください。

## プレビューキャッシュが 0 フレームのままになる

**原因:** キャッシュ対象のフレームがまだ描画されていないか、キャッシュが無効になっているか、現在のプロジェクトがキャッシュ非対応の状態です。
**Settings** の **Preview cache** 設定の下に、計算済みメモリー使用量と保持フレーム数が表示されます。プロジェクトをキャッシュできない場合は、同じ行の末尾に **Not caching:** と理由が表示されます。

**対処:**

1. **Settings** の **Not caching:** に続く理由を確認します。**Preview cache** の上限を増やしても、これらの条件は解除されません。
2. **Preview cache** を `0` より大きく設定します (既定値は `512` MiB です)。
3. まず通常通りフレームを描画します。同じフレームとプロジェクト状態へ戻るとキャッシュが再利用されます。
4. 再確認までの間に編集、リソース読み込み、解像度変更、プラグイン切り替えを行わないでください。これらを行うとキャッシュは無効化されます。
5. 時間エフェクトを含む動画プロジェクトや描画が重いシーンでは、待機中の事前レンダリングは行われません。動画が表示されている間は、再生を一時停止して約 0.8 秒操作を止めた後に正確なデコードとキャッシュが行われます。
6. 以前メモリー確保に失敗した場合、設定値を上げてもセッション上限は下がったままになります。GPU コンテキストの喪失が 2 回起きた場合は、エディターを再読み込みしてキャッシュを再有効化してください。

キャッシュの詳しい条件は [プレビューとキャッシュ](/docs/ja/workflow/preview-and-cache/) を参照してください。

## プラグイン不足やエラーで書き出しが拒否される

**原因:** プロジェクトにコミュニティエフェクトが含まれており、現在のプレビューではコミュニティエフェクトの書き出しに対応していません。

**対処:** エディターに **Export with missing or failed plugins** が表示されたら、1 回限りのバイパスを承認します。
閉じたコンポジション内を含め、すべてのフレームでコミュニティエフェクトを除外して書き出します。
プロジェクトの内容自体は変わらず、この選択はその 1 回の書き出しにのみ適用されます。完全に書き出すには、不足しているパッケージを導入または修復してください。

## プロジェクトを開くとプラグインやアセットが不足する

**原因:** プロジェクトに必要なプラグインが無効になっているか、アセットファイルが見つからないか読み込みに失敗しています。

**対処:**

1. 必要なプラグイン名が表示された場合は、**Plugins** でそのプラグインを有効にします。保存済みのエフェクト、マテリアル、オブジェクト設定が復元されます。
2. 欠落または失敗したファイルは、[アセットとプロジェクトファイル](/docs/ja/workflow/assets/) の修復手順で再接続します。書き出しや新規保存の前に修復を済ませてください。
3. 修復したプロジェクトを新しい `.pz` アーカイブとして保存し、問題ないことを確認するまで元のファイルも残しておきます。

## エディターが重い、または GPU メモリーが不足する

**原因:** 操作のたびに重いシーンがフル解像度で再描画されています。

**対処:**

1. プレイヤーツールバーで **Pause drawing** をクリックし、品質を **1/8 quality** にします。
2. 確認したい変更の後だけ **Render once** をクリックします。
3. **Settings** で **Preview cache** の上限を上げ、同じフレームをメモリーから再表示できるようにします。
4. 書き出し中に GPU メモリー不足やコンテキスト喪失が出た場合は、他のプロジェクトを閉じ、出力サイズを下げてからやり直してください。

重いプロジェクトの作業手順は [プレビューとキャッシュ](/docs/ja/workflow/preview-and-cache/) にまとめています。

## 再生ヘッドが動いているのに動画が 1 フレームのまま止まる

**原因:** その動画クリップのデコード中に、ストリーミング動画デコーダーが停止しました。新しいフレームが 1.5 秒間届かない場合、Zoidium はその動画をブラウザー内蔵のデコーダーへ自動で切り替えます。

**対処:** それでも動画が 1 フレームのまま止まる場合は、デバッグログを保存してプロジェクトと一緒に報告してください。

1. **Settings** を開きます。
2. **Debug information** セクションの **Download debug log** をクリックします。デコーダーのフォールバックもログに記録されます。
3. ファイル内容を確認したうえで、ログとプロジェクトをバグ報告に添付します。

## バグ報告にデバッグログを添付する

**原因:** 環境情報がない報告は再現が困難です。

**対処:**

1. **Settings** を開きます。
2. **Debug information** セクションの **Download debug log** をクリックします。
3. ファイル内容を確認したうえで報告に添付します。

ログには OS、ブラウザー、有効なプラグイン、直近のクラッシュ情報が記録されます。プロジェクトのデータ本体は含まれません。
