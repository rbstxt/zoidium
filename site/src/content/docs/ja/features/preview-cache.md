---
title: プレビューキャッシュ
---
Settings > Preview cache では、描画が終わったエディターフレームのカウント対象メモリーの上限を設定します。デフォルトは 512 MiB で、0 にするとキャッシュが無効になります。設定できる値は最大 16384 MiB で、保持できるフレーム数は最大 8192 です。これは上限であり、予約メモリーではありません。

## キャッシュの対象

完全なフレームは GPU 上でコピーでき、同じフレームとプロジェクト状態に戻ったときに再表示できます。キャッシュにないフレームはリアルタイムで描画します。リソースの読み込み、プロジェクトの編集、解像度やプラグインの変更があると、関連するキャッシュは無効になります。書き出しやスポイトツールの描画は独自の経路を通り、保存済みプロジェクトの内容はキャッシュで変わりません。

一時停止して操作を止めている間、対象のシーンはプロジェクトの内部コピーを使って一定範囲を事前描画します。動画項目のデコード範囲内にある候補フレームでは事前描画を省略します。この範囲には、スケジュールの先読み用の余白を含みます。時間サンプリングやマルチサンプルモーションブラーを使う動画プロジェクトでは、アイドル時の事前描画をすべて省略します。同期描画に 50 ms を超えるシーンでも事前描画を省略します。通常どおり表示したフレームは保持できます。

映像が表示されている間は、エディターの映像再生がフレーム単位で正確ではないため、その場の描画は保持しません。代わりに、再生を一時停止して約 0.8 秒操作がないと、現在のフレームをプロジェクトの内部コピーで正確にデコードして保持します。再生中のフレームや他のフレームは、今までどおりその場で描画します。この状態では、**Settings** に **Video frames are not cached in this preview.** または **Preparing video frames for the preview cache.** と表示されます。

## プラグインの検証

プラグインの承認には、インストールされたバージョンと、ブラウザーの出力検証で使用したレンダリングソースのフィンガープリントを記録します。承認の記録は `plugins/core/output-frame-approvals.js` に保存します。ランタイムソース、プラグインのマニフェスト、アセット、起動順序、有効化のデフォルト値、または検証用フィクスチャが変更されると、`pnpm run verify` は失敗します。デプロイ用のバージョン番号や再ビルドされたバンドルは、変更のない承認を無効にしません。

ブラウザーの出力検証では、GPU から読み取ったバイト列を、同じフレームで新しく読み込んだプロジェクトのライブ描画と比較します。検証項目には、順方向、逆方向、繰り返しのシーク、時間エフェクト、プライベートなコピーで事前レンダリングしたフレーム、短時間の **Full quality** 確認を含みます。フィクスチャが失敗したプラグインは、ライブプレビューを使用します。検証ツールの `--write` オプションは、全項目の検証後に承認を記録します。フィルターを指定した実行では、承認を更新できません。

## キャッシュが空の場合

プレビューフレームを保持または再利用できない場合、使用量の注記に **Not caching:** と現在の理由を表示します。メモリーの上限を上げても、これらの確認は省略されません。

- コミュニティコンテンツや、キャッシュの検証が済んでいないプラグインバージョンはライブプレビューになります。注記には、必要なプラグインと、バージョンが判明している場合はその番号を表示します。
- フレームサンプラーを使わない時間操作はライブ評価になります。Smart Motion Blur 自体はキャッシュを無効にしませんが、プラグインのバージョンは検証に合格する必要があります。
- プラグインの読み込み中はキャッシュを止めます。必要なプラグインにエラーがある場合もキャッシュを止めます。使っていないプラグインのバンドル読み込みエラーは、そのプラグインの有効化処理が一度も始まっていない場合に限り、キャッシュを止めません。有効化処理の開始後にエラーがある場合は、すべてのプロジェクトでキャッシュを止めます。プラグインのコードが共有ファクトリーを変更している可能性があるためです。Core のエラーは常にキャッシュを止めます。
- フレームを保持する前に、リソースの読み込み、フレームの準備、正確な動画フレームのデコードが終わっている必要があります。
- プロジェクトの検証に 8 ms を超える時間がかかる場合、変更後の状態の検証は、再生の停止と編集のアイドル状態を待ってから行われます。
- 3D 編集カメラや、1 フレーム分より小さいメモリー上限も、新しいキャプチャーを妨げます。

注記は次のプレビュー描画後に更新されます。**Pause drawing** は通常のプレビュー描画を止め、描画せずに状態を表示します。描画を一時停止していても、**Render once** で完全なフレームをキャプチャーできます。アイドル時の事前描画は独自の条件に従います。

## メモリー制限

カウント対象の RGBA8 バイト数には、ドライバーの負荷やその他のレンダーターゲットは含まれません。メモリーの割り当てに失敗したりコンテキストを喪失したりすると、セッションの上限が下がり、設定を上げても元に戻りません。2 回目のコンテキスト喪失が起きると、再読み込みまでキャプチャーは無効のままです。詳しい動作は、[プレビューキャッシュのメモリ](/docs/ja/development/project-compatibility/#プレビューキャッシュのメモリ)を参照します。

4096 MiB を超える値を選ぶと、Settings に GPU の空きメモリーがその分だけ必要だという警告が表示されます。内蔵 GPU は、どのオペレーティングシステムでもシステム RAM とメモリーを共有します。
