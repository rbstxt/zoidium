**Player+** と **Preview cache** を使うと、プロジェクトや書き出しの解像度を変えずに、重いシーンでも軽快に編集できます。

## Player+ でビューポート描画を制御する

**Player+** は既定で有効になっており、プレイヤーツールバーに描画・品質・再生速度コントロールを追加します。

| コントロール | 動作 |
| --- | --- |
| **Pause drawing** | 編集中の自動再描画を一時停止します。再生ヘッドや音声の再生は止めません。 |
| **Render once** | 描画停止中の変更を含めて、現在のフレームだけを 1 回描画します。 |
| **Resume drawing** | 自動再描画を再開します。起動時は有効です。 |
| **Preview quality** | ビューポートの縦横ピクセル解像度を **Full quality** (既定)、**1/2 quality**、**1/4 quality**、**1/8 quality** に縮小します。選択はローカルに保存されます。 |
| **Playback speed** | 再生速度を **Paused**、**0.25x**、**0.5x**、**0.75x**、**1x**、**1.25x**、**1.5x**、**2x** から選びます。逆再生や倍速を含む **J** / **K** / **L** シャトル操作にも追従します。 |

ネイティブ音声の再生は、選択した正の再生速度に追従します。
**Playback speed** と **Preview quality** はエディター内のプレビューだけに効きます。保存済みプロジェクト、プロジェクト解像度、書き出し設定には影響しません。

## 重いプロジェクトを快適にプレビューする

1. **Plugins** で **Player+** が有効であることを確認します。
2. プレイヤーツールバーの **Pause drawing** をクリックします。
3. **Preview quality** を **1/8 quality** にします。
4. プロジェクトを読み込むか、編集を進めます。
5. 確認したいフレームへ再生ヘッドを移動し、**Render once** をクリックします。
6. 細部を確認したいときだけ **Preview quality** を **1/4 quality**、**1/2 quality**、または **Full quality** に上げ、もう一度 **Render once** をクリックします。
7. 負荷の高い編集を続ける前に **1/8 quality** へ戻すか、自動更新に戻したいときに **Resume drawing** をクリックします。

## プレビューキャッシュでフレームを再利用する

プレビューキャッシュは描画済みのエディターフレームを GPU メモリーに保持し、同じフレーム・同じプロジェクト状態へ戻ったときに再計算なしで表示します。

1. **Settings** を開きます。
2. **Preview cache** に上限メモリーを設定します。既定値は `512` MiB で、`0` にすると無効になります。
3. コントロール下の使用状況行で、計算済みメモリー、保持フレーム数、現在のステータスを確認します。

設定可能な範囲は `0` ～ `16384` MiB で、保持できるフレーム数は最大 `8192` フレームです。この値は上限であり、最初からメモリーを予約するものではありません。
キャッシュ上限と **Player+** のプレビュー品質は別の設定です。キャッシュを増やしても、未描画フレームの初回描画は速くなりません。

### キャッシュに入るフレーム

- 完成したビューポートフレームを GPU 上にコピーし、同じフレームとプロジェクト状態で再利用します。キャッシュにないフレームはライブ描画されます。
- プロジェクトの編集、リソース読み込み、解像度やプラグインの変更があると、関係するキャッシュは無効化されます。
- 書き出しやスポイト用の描画は別経路のため、キャッシュには入りません。
- 一時停止して待機している間、条件を満たすシーンは前後一定範囲のフレームを事前レンダリングします。動画クリップのデコード範囲内、時間エフェクトを含む動画プロジェクト、描画が遅いシーンでは待機中の事前レンダリングを省略します (通常描画したフレームの保持は行われます)。
- 動画が表示されている間は通常再生がフレーム厳密ではないため、再生中の描画はキャッシュされません。再生を止めて約 0.8 秒操作しないでいると、現在のフレームと前方最大 30 フレーム、後方最大 4 フレームが正確にデコードされて保持されます。この状態では **Settings** に **Video frames are not cached in this preview.** または **Preparing video frames for the preview cache.** と表示されます。

### キャッシュされないとき

フレームを保持または再利用できない場合、**Settings** の使用状況行に **Not caching:** と理由が表示されます。メモリー上限を増やしても、これらの条件は解除されません。

- **未検証のプラグインやサードパーティ製アイテム:** プロジェクトで必要なプラグインはすべて有効で、このビルドのプレビューキャッシュ検証リストで承認されたバージョンと一致する必要があります。サードパーティ製プラグインのアイテムや未承認バージョンのプラグインを含むプロジェクトはキャッシュせずライブ描画になります。プラグインのバージョンが検証に通らない場合は、ステータス行にプラグイン名とバージョンが表示されます。
- **キャッシュ非対応の時間エフェクト:** フレームをキャッシュできない時間エフェクトがあるとライブ描画になります。Smart Motion Blur 単体ではキャッシュを無効にしませんが、プラグイン版の検証に通る必要があります。
- **フレーム間で状態を持つエクスプレッション:** 前のフレームの値を保持しうるエクスプレッションがあるとライブプレビューになります。ライブ描画と書き出しの結果は変わりません。
- **読み込み中または失敗したプラグイン:** 読み込み中のプラグインがあるとキャッシュされません。未使用プラグインのバンドル読み込みエラーは、そのプラグインの起動処理が始まっていない場合に限りキャッシュを許可します。起動が始まった後や、有効・必須・Core プラグインのエラーがある場合は、そのプラグインを無効化または修復するまで全プロジェクトでキャッシュが止まります。
- **読み込み・検証の待機中:** リソース読み込み、フレーム準備、厳密な動画デコードが終わるまでは保持されません。プロジェクト検証が重い場合は、再生が止まり編集が待機状態になるまで検証を待ちます。
- **3D 編集カメラまたは容量不足:** 3D 編集カメラが有効な間や、上限メモリーが 1 フレーム未満の場合は新規キャプチャされません。

使用状況行は次のプレビュー描画後に更新されます。**Pause drawing** の状態は描画なしで反映され、描画停止中でも **Render once** で完成フレームをキャッシュできます。

### GPU メモリー上限

`4096` MiB を超える値を設定すると、**Settings** は指定量の空き GPU メモリーが必要である旨の警告を表示します。統合 GPU では、どの OS でもシステム RAM とメモリーを共有します。

GPU メモリーの確保失敗や WebGL コンテキスト喪失が発生すると、内部のセッション上限が下がり、設定値を上げても上書きできません。コンテキスト喪失が 2 回発生すると、エディターを再読み込みするまでキャッシュは無効のままになります。詳しい挙動は [プレビューキャッシュのメモリー](/docs/ja/development/project-compatibility/#プレビューキャッシュのメモリ) を参照してください。
